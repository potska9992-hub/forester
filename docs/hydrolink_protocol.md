# HydroLink v1: протокол радиосвязи пульта и приёмника

Версия протокола: 1 (HL_PROTO = 1). Реализации: `pult/pult.ino` (блок «РАДИО: HydroLink v1») и `receiver/receiver.ino` (радиозадача на ядре 0). Документ проверен по коду обеих прошивок (31.10.2026, pult 1.3 и receiver 1.0). Подробная история решений: `remote_config.md` §26..§31, §52.

Все числа little-endian. Пакет не длиннее 64 байт. Пакет с неверной CRC или чужой парой молча отбрасывается.

## 1. Радио

| Параметр | Значение |
|---|---|
| Чип | SX1262 (Heltec Wireless Stick Lite V3), библиотека RadioLib 7.1.2 |
| Частота | 868.0 МГц |
| SF / BW / CR | SF7, 250 кГц, CR 4/5 (значение 5) |
| Sync word / преамбула | 0x12 / 8 |
| TCXO | 1.8 В; если инициализация не прошла, повтор с TCXO 0 |
| Антенный ключ | DIO2 (`setDio2AsRfSwitch(true)`) |
| Мощность | пульт: настройка TX power; приёмник: параметр RX POWER (2..22 dBm, по умолчанию 10) |
| Токовый лимит PA | 140 мА при мощности выше 14 dBm, иначе 60 мА |
| Пины (оба устройства) | NSS 8, SCK 9, MOSI 10, MISO 11, RST 12, BUSY 13, DIO1 14 |

Время в эфире при SF7/BW250: пакет управления 7..12 байт около 18..23 мс, телеметрия 36 байт около 40 мс. Реальная частота управления не выше 30..40 пакетов в секунду.

Полудуплекс: приёмник отвечает не раньше чем через 5 мс после конца приёма (RF_TURNAROUND_MS), чтобы пульт успел переключиться на приём. Очередь ответов приёмника: 4 пакета.

## 2. Общий формат пакета

```
[0]      тип (старший полубайт) | флаги (младший)
[1..2]   ID пары (uint16)
[3]      номер или метка (зависит от типа)
...      тело
[n-2..n-1] CRC16-CCITT по всем предыдущим байтам, младший байт первым
```

CRC16: полином 0x1021, начальное значение 0xFFFF, без инверсии входа и выхода, без финального XOR.

ID пары: `bindId` 32 бита, `pair = (bindId ^ (bindId >> 16)) & 0xFFFF`; если получилось 0 или 0xFFFF, то `pair ^= 0x5A5A`. По умолчанию bindId = 0xA5C3E17B, пара 0x44B8. Пакет с чужой парой игнорируется (кроме BIND, он идёт с парой 0xFFFF).

| Тип | Имя | Направление | Длина |
|---|---|---|---|
| 1 | CONTROL | пульт → приёмник | 7 + n |
| 2 | TELEM | приёмник → пульт | 36 |
| 3 | CFG | пульт → приёмник | 12 |
| 4 | ACK | приёмник → пульт | 12 |
| 5 | BATCH | приёмник → пульт | 8 + 2n |
| 6 | NET | пульт → приёмник | 10 + имя + пароль |
| 7 | INFO | приёмник → пульт | 8 + длина текста |
| 8 | BIND | пульт → все | 10 |
| 9 | BINDOK | приёмник → пульт | 10 |

## 3. CONTROL (тип 1)

```
[0] 0x10 | флаги   [1..2] пара   [3] номер пакета (8 бит, с переходом)
[4] маска каналов   [5..] int8 по одному на установленный бит маски (по возрастанию канала)   CRC16
```

- Флаги: бит0 (1) E-Stop; бит1 (2) запрос телеметрии REQT; бит2 (4) тест рычага (пульт на экране правки параметров, рычаг работает как тестовый); бит3 (8) «пульт только что включён» (приёмник сейчас флаг не использует).
- Значения: -100..+100 (процент хода рычага, минус = сторона B). Приёмник ограничивает значение этим диапазоном. Канал вне маски = 0. Длина пакета должна быть ровно 7 + число единиц в маске, иначе пакет отбрасывается.
- Heartbeat = CONTROL с маской 0 (7 байт).
- Приёмник считает пропущенные пакеты по разрыву номеров (`gap = seq - last - 1`, учитывается при gap < 128, сумма насыщается на 255) и отдаёт счётчик в телеметрии.
- Любой корректный CONTROL обновляет таймер связи приёмника. Нет CONTROL дольше LINK TMO (по умолчанию 500 мс): все выходы в ноль, killswitch с причиной 3.
- E-Stop: флаг 1 во всех пакетах, пока E-Stop активен. Приёмник при флаге аппаратно сразу выключает OE и EN, остальное делает в основном такте. Снятие E-Stop = пакет без флага.
- Телеметрией приёмник отвечает только на пакет с флагом REQT, сразу после приёма.

Примеры (пара 0x44B8):

```
CONTROL, номер 1, маска 0x03, CH1 = +50, CH2 = -100:  10 b8 44 01 03 32 9c 13 a6
Heartbeat, номер 2:                                    10 b8 44 02 00 4b c6
Heartbeat + запрос телеметрии, номер 3:                12 b8 44 03 00 f9 b1
```

## 4. Тайминги пульта

- Связи нет (поиск): CONTROL с REQT каждые 150 мс (HL_SEARCH_MS).
- Связь есть: REQT каждые 1000 / telemRate мс (по умолчанию 3 раза в секунду); если ответа нет, следующий запрос через 150 мс.
- Быстрый режим: пока любой канал не ноль, E-Stop или тест рычага: пакеты подряд, пауза 2 мс (HL_GAP_MS) после конца передачи и после конца ожидания ответа.
- Heartbeat: после 300 мс всех нулей (HL_HB_AFTER_MS) каждые 66 мс (HL_HB_MS), около 15 раз в секунду.
- Ожидание ответа: 90 мс после конца своей передачи (HL_RESP_MS).
- Связь на пульте считается потерянной, если нет ни одного корректного пакета от приёмника дольше 3000 / telemRate + 450 мс.
- Пока идут синхронизация, привязка или любая длинная запись настроек, пульт шлёт нули (маска 0) и чередует CONTROL с CFG: приёмник продлевает связь по CFG и NET не дольше 3 с после последнего CONTROL (cfgKeepAlive), поэтому серию CFG нужно перемежать пакетами CONTROL. Пульт 1.3 при групповой записи (All Channels, Copy to All) шлёт CONTROL каждые 250 мс (при тесте рычага каждые 60 мс).

## 5. CFG (тип 3), 12 байт

```
[0] 0x30 | бит0 (1 = сохранить в NVS приёмника)   [1..2] пара   [3] метка (tag)
[4] операция   [5] параметр или команда   [6] канал   [7] сторона (0 A, 1 B)   [8..9] значение uint16   [10..11] CRC16
```

Метка: 1..255, новая для каждого нового запроса. Повтор той же попытки идёт с ТОЙ ЖЕ меткой.

Операции: 0 SET, 1 GET (ответ ACK со значением из RAM), 2 BATCH (ответ пакетом BATCH со СОХРАНЁННЫМИ значениями, NVS), 3 CMD (команда), 4 NET (внутренне; на радио уходит пакетом NET).

### 5.1 Параметры (RXP, 15 штук)

Область: SOL = на соленоид (канал и сторона, 16 штук), CH = на канал (8), GLOB = общий (1). Для CH поле «сторона» игнорируется, для GLOB игнорируются и канал, и сторона.

| № | Имя | Область | Пределы | Шаг | По умолчанию | Единица |
|---|---|---|---|---|---|---|
| 0 | LIMIT | SOL | 5..100 | 1 | 20 | 0.1 А (лимит тока) |
| 1 | DUTY | SOL | 0..1000 | 5 | 50 | 0.1 % (стартовый ШИМ) |
| 2 | MAX DUTY | SOL | 100..1000 | 5 | 600 | 0.1 % |
| 3 | RAMP UP | CH | 0..2000 | 50 | 200 | мс |
| 4 | RAMP DN | CH | 0..2000 | 50 | 200 | мс |
| 5 | ENABLE | CH | 0..1 | 1 | 1 | |
| 6 | OVL DELAY | GLOB | 20..1000 | 10 | 150 | мс |
| 7 | LINK TMO | GLOB | 200..2000 | 50 | 500 | мс |
| 8 | PWM FREQ | GLOB | 50..500 | 10 | 100 | Гц |
| 9 | DITH AMP | GLOB | 0..20 | 1 | 0 | % |
| 10 | DITH FREQ | GLOB | 10..60 | 5 | 30 | Гц |
| 11 | RX POWER | GLOB | 2..22 | 1 | 10 | dBm |
| 12 | CONTROL | GLOB | 0..1 | 1 | 0 | 0 PWM, 1 CURRENT |
| 13 | START I | SOL | 0..100 | 1 | 5 | 0.1 А (режим CURRENT) |
| 14 | MAX I | SOL | 5..100 | 1 | 15 | 0.1 А (режим CURRENT) |

Приёмник ограничивает значение пределами и возвращает в ACK применённое. Шаг проверяет и применяет пульт, приёмник шаг не проверяет. Порядок и пределы должны совпадать на обеих сторонах: от порядка зависит CRC8 конфигурации (раздел 9).

SET без бита сохранения меняет только RAM приёмника. С битом: RAM и NVS.

### 5.2 Команды (операция 3, поле «параметр» = код команды)

| Код | Имя | Значение | Поведение приёмника |
|---|---|---|---|
| 0x01 | HLC_PROTO | версия протокола (1) | ACK статус 1, если не 1 (пульт показывает «Protocol mismatch») |
| 0x02 | HLC_CHMASK | маска включённых каналов пульта | запоминает |
| 0x03 | HLC_CHTYPES | маска каналов типа T_SW3 (тумблер) | запоминает |
| 0x04 | HLC_TXPWR | TX power пульта, dBm | запоминает |
| 0x10 | HLC_FACTORY | ключ 0xA55A | статус 1 при другом ключе; статус 2, если рычаги не в нуле 300 мс, E-Stop, аварийная кнопка, сбой или открыт Wi-Fi; иначе сброс RAM и NVS настроек к заводским, счётчик перезагрузок +1, ACK 0. Привязка (bindId) не затрагивается |
| 0x20 | HLC_WIFI_PHONE | | открыть Wi-Fi для телефона (Update/Test) |
| 0x21 | HLC_WIFI_GH | | подключиться к сетям (из NET) и обновиться с GitHub |
| 0x22 | HLC_WIFI_OFF | | закрыть Wi-Fi; статус 3, пока идёт загрузка прошивки (состояния 5, 13, 14) |
| 0x23 | HLC_WIFI_YES | | подтвердить установку найденной версии; статус 2, если не в состоянии 12 |

WIFI_PHONE и WIFI_GH: статус 3, если Wi-Fi уже открыт или запрос в очереди; статус 2, если рычаги не в нуле 300 мс, E-Stop или аварийная кнопка (при сбое реле Wi-Fi открыть можно).

Неизвестный код команды: ACK статус 1.

## 6. ACK (тип 4), 12 байт

```
[0] 0x40   [1..2] пара   [3] метка из запроса   [4] статус   [5] параметр   [6] канал   [7] сторона   [8..9] применённое значение   CRC16
```

Статус: 0 ок, 1 ошибка (неверный параметр, значение, ключ, неизвестная команда), 2 отказ сейчас, 3 занят.

- Приёмник отвечает на каждый CFG и NET сразу. Пульт ждёт ACK до 90 мс после конца своей передачи; нет ответа: до 3 попыток (HL_CFG_TRIES) с той же меткой, затем «RX no answer» и откат значения.
- Идемпотентность: для CMD и NET приёмник хранит последний ответ и метку. Повтор запроса с той же меткой не выполняется второй раз, а повторяет сохранённый ACK. SET, GET и BATCH безопасно повторяются сами (результат тот же).
- ACK для NET: параметр 0xE0, канал = слот, статус 0 или 1.
- Не отвечать на пакеты с неверными CRC или парой.

## 7. BATCH (тип 5), ответ на CFG операции 2

```
[0] 0x50   [1..2] пара   [3] метка   [4] параметр   [5] n   [6..] n значений uint16   CRC16
```

Длина 8 + 2n. n: SOL = 16 (индекс = канал * 2 + сторона), CH = 8, GLOB = 1. Значения СОХРАНЁННЫЕ (NVS), не RAM. Для SOL 40 байт. Неверный параметр: ACK статус 1.

## 8. NET (тип 6) и INFO (тип 7)

NET, пульт → приёмник:

```
[0] 0x60   [1..2] пара   [3] метка   [4] слот (0..2)   [5] всего сохранённых сетей
[6] длина имени (≤ 32)   имя   длина пароля (≤ 63)   пароль   CRC16
```

Приёмник хранит сети только в RAM, до закрытия Wi-Fi. Ответ ACK с параметром 0xE0. Статус 1: слот ≥ 3, имя или пароль слишком длинные, или GitHub-обновление уже идёт (состояние ≥ 10). Перед HLC_WIFI_GH пульт отправляет все сети подряд, по одному пакету, потом команду. Приёмник считает сети принятыми, если в RAM есть хоть одно имя.

INFO, приёмник → пульт, без подтверждения:

```
[0] 0x70   [1..2] пара   [3] 0   [4] вид   [5] длина текста (≤ 23)   текст   CRC16
```

Вид 1 = версия, найденная на GitHub (состояние 12). Вид 2 = имя сети Wi-Fi приёмника «RX-xxxx» (состояния 2 и 3). Приёмник шлёт INFO вместо телеметрии не чаще раза в 1.5 с, когда пришёл CONTROL без REQT.

## 9. Телеметрия TELEM (тип 2), 36 байт

| Байты | Поле |
|---|---|
| 0 | 0x20 |
| 1..2 | пара |
| 3 | номер телеметрии (растёт) |
| 4 | последний принятый номер управления |
| 5 | SNR, с которым приёмник слышит пульт (int8, дБ) |
| 6 | пропущено пакетов управления с прошлой телеметрии (насыщение 255) |
| 7..14 | ток в импульсе по каналам, 0.1 А (uint8, насыщение 255); у отключённого по перегрузке: пиковый ток |
| 15..22 | ШИМ по каналам, int8, -100..100 % (минус = сторона B) |
| 23 | маска ограничения тока (бит = канал) |
| 24 | маска перегрузки |
| 25 | маска обрыва |
| 26 | сторона нагрузки/ошибки (бит канала, 1 = сторона B) |
| 27 | статус: бит0 killswitch, биты 1..2 причина (0 пульт, 1 кнопка приёмника, 2 сбой, 3 нет связи) |
| 28 | напряжение бортсети приёмника, 0.1 В |
| 29 | RSSI, с которым приёмник слышит пульт (int8, dBm) |
| 30 | счётчик перезагрузок приёмника (8 бит; +1 при старте и после FACTORY) |
| 31 | CRC8 сохранённой конфигурации |
| 32 | состояние Wi-Fi (раздел 11) |
| 33 | параметр Wi-Fi (процент или код ошибки) |
| 34..35 | CRC16 |

Приоритет причины killswitch (приёмник): сбой > кнопка приёмника > E-Stop пульта > нет связи.

Пульт: событие «RX alarm» при причине 1, «RX fault» при причине 2, «Batt RX» при напряжении ниже 10.5 В (HL_RXBATT_LOW = 105; 0 = неизвестно, не считается).

## 10. Синхронизация настроек

Пульт хранит копию СОХРАНЁННЫХ настроек приёмника (NVS пульта, пространство «rxcopy») и показывает её в меню Receiver. Источник истины: приёмник.

Когда запускается синхронизация: (а) при первой телеметрии после включения пульта; (б) при изменении счётчика перезагрузок в телеметрии; (в) при несовпадении CRC8 телеметрии с CRC8 копии пульта (однократно: если после синхронизации CRC снова не сошёлся, пульт не зацикливается на этом значении, пока оно не изменится).

Шаги (HL_SYNC_STEPS = 4 + 15 = 19), по одному запросу, без сохранения: 1) CMD HLC_PROTO = 1; 2) CMD HLC_CHMASK; 3) CMD HLC_CHTYPES; 4) CMD HLC_TXPWR; 5..19) BATCH параметров 0..14. Сбой шага (кроме TXPWR) прерывает синхронизацию, повтор через 2 секунды. Во время синхронизации пульт шлёт нули, правки блокированы.

CRC8: полином 0x07, init 0, без инверсии, без финального XOR. Данные: СОХРАНЁННЫЕ значения всех параметров p = 0..14; для каждого параметра: SOL: канал 0..7, для каждого сторона 0..1; CH: канал 0..7; GLOB: одно значение. Каждое значение uint16 подаётся младшим байтом, затем старшим. Значения должны быть теми же, что в NVS приёмника (после ограничения пределами).

Ограничение (receiver 1.0): значения RAM, изменённые без сохранения (живая правка из меню Receiver), приёмник откатывает к сохранённым только при перезагрузке, а не при потере связи. Пульт при потере связи сбрасывает свою копию к сохранённой (rxRevertAll). Подробнее: remote_config.md §53.

## 12. BIND (тип 8) и BINDOK (тип 9)

BIND, пульт → все:

```
[0] 0x80   [1..2] 0xFFFF   [3] номер   [4..7] новый bindId (uint32)   CRC16
```

Пульт шлёт BIND каждые 150 мс (HL_BIND_MS), пока пользователь не отменит или не придёт ответ. Приёмник принимает BIND только в режиме привязки (долгое нажатие USER 3 с, режим длится 60 с) и ещё 4 с после успешной привязки (повтор, если пульт не получил ответ и bindId тот же). Приёмник запоминает bindId в NVS, сбрасывает счётчик номеров и отвечает:

```
BINDOK: [0] 0x90   [1..2] НОВАЯ пара   [3] номер из запроса   [4..7] bindId (эхо)   CRC16
```

Пульт принимает BINDOK, если эхо bindId совпало, и сохраняет новый bindId. Во время привязки пульт шлёт нули.

## 13. Чек-лист для новой реализации

1. Радио с параметрами раздела 1, ID пары, CRC16.
2. CONTROL: маска, heartbeat, номера, E-Stop, потеря связи, ответ телеметрией на REQT.
3. Все параметры раздела 5.1 с пределами и значениями по умолчанию, RAM и NVS.
4. ACK на CFG и NET, BATCH, команды раздела 5.2, идемпотентность по метке.
5. CRC8 конфигурации, счётчик перезагрузок в NVS.
6. BIND/BINDOK, Wi-Fi (Update, Test, GitHub) со состояниями раздела 11.
7. Телеметрия по раздел 9: ток, ШИМ, маски, напряжение.
